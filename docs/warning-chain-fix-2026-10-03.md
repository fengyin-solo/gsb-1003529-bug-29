# 预警阈值链路修复记录（2026-10-03）

## 一、定位：四处对不上的根因

沿「阈值配置 → 水位异常判定 → 巡检生成」现有链路排查，仓库此前只有通用 CRUD 骨架：

1. **配置列表 / 配置面板**（`views/warning/index.vue`、`data/modules.ts`）
   - 蓝/黄/橙/红阈值在示例数据里是字符串（`"预警阈值样例1"`），没有数值解析与递增校验，面板也不存在。
   - `生效状态` 字段与动作流转状态各写各的，列表展示的列没有版本、生效/停用时间。
2. **通用动作流转**（`api/local-service.ts:runAction`）
   - `abnormal` 靠动作名前缀猜（`停用` 前缀命中负向动作，导致已生效配置被点停用后 `abnormal=true`，但判定链路根本不读它）；
   - `pending` 一律按「是不是最后一个状态」推断；
   - 预警阈值动作和其他模块共用同一套通用流转，没有任何阈值语义。
3. **水位异常判定**（`views/waterlevel/index.vue`）
   - 完全不存在判定逻辑：`当前水位` 是字符串，没有级别字段，没有配置版本快照，配置停用后旧级别是否残留无从谈起——因为级别从没被算过。
4. **巡检处理入口**（`views/inspection/index.vue`、`data/seed.ts`）
   - 巡检记录与阈值、水位没有外键关系，待办不由判定产生，也不会随发布/停用回退。

即：配置、面板、判定、巡检四处没有共同口径，蓝黄橙红冲突时各处不可能算出一致结果，反复发布也没有版本概念，旧版阈值天然残留。

## 二、统一后的口径（全部收敛到 `src/data/warning-chain.ts`）

1. **停用口径**：仅 `status === '已生效'` 的配置参与判定（`activeConfigFor`）。草稿、已调整、已停用一律不生效；停用在同一事务内重判该站点水位并撤回未处置待办，旧级别即时失效。
2. **冲突优先级**：
   - 配置合法性：`0 ≤ 蓝 < 黄 < 橙 < 红` 必须严格递增，面板保存与发布共用 `validateThresholds`，冲突配置无法保存/发布；
   - 判定：`evaluateLevel` 取「达到阈值的最高级别」，红 > 橙 > 黄 > 蓝，是全仓库唯二的级别计算入口（另一处只是它的批量调用），列表、面板、水位、巡检不再各自写条件。
3. **版本口径**：同一「站点编号 + 监测类型」为一个配置组，组内仅版本号最大的已生效配置生效；「调整阈值」生成新草稿（版本号 +1），发布后旧版统一置「已调整」，反复发布只有一版阈值存活。
4. **并发发布**：`publishWarning(id, expectedRevision)` 做组版本乐观锁；每个写事务开始 `reloadCache()` 强制重读最新提交（多标签页另有 `storage` 事件使缓存失效）。基线落后即整单拒绝，只接受一个版本；已有更新在效版本时旧草稿也拒绝发布。
5. **事务与回退**：发布/停用/全量重判都走 `runTransaction`——在内存快照上依次改 配置 → 水位判定 → 巡检待办 → 留档，任一判定失败（如水位值非数值）抛错且**不提交**，统计（由已提交数据实时汇总）与待办一起回退；全部成功后由 `commitAll` 单次写入 localStorage。
6. **巡检待办联动**（`syncInspectionTodo`）：开放水位记录（已采集/待审核）有级别则保证一条 `待办来源=阈值判定`、`水位记录ID` 关联的「待巡检」待办，级别变化更新内容、级别消失（停用/阈值抬高）直接撤回；不新建手工待办、不删除已处置待办。

## 三、历史调阈值是否重算已归档记录——决策

**决策：不重算已归档记录，当时结论留档。**

- 归档定义：水位记录状态为「已通过 / 异常值」（终态），或巡检待办已「已处置」。
- 归档水位行冻结 `预警级别 / 触发配置版本号 / 判定时间` 三元组快照，发布、停用、全量重判都不改；其名下未处置的自动待办按记录终态同步关闭，处置说明里保留触发级别。
- 理由：已审核/已处置结论可能已对外发布或触发过响应，用新阈值倒改历史会让台账与当时处置依据自相矛盾；需要追溯时以配置版本号 + `warningAudit` 留档为准。示例数据中 ST-02 的 WATE-0003（42m，在 v1 口径下橙色，v2 口径下已不报警）即为留档样例。
- 开放记录（已采集/待审核）每次发布、停用、手动「按生效阈值重新判定」都按当前唯一生效配置重算。

## 四、变更清单

- `src/data/warning-chain.ts`（新增）：阈值校验、级别判定、生效配置解析、版本乐观锁、调整/发布/停用事务、水位重判、巡检待办同步、留档、统计。
- `src/data/local-store.ts`：存储版本升级 v2（旧缓存结构不兼容）、`commitAll` 事务提交点、`reloadCache` 写前重读、跨标签页 `storage` 失效。
- `src/api/local-service.ts`：预警动作改走统一链路（拒绝通用流转）；水位动作后异常标记只认判定快照、进终态时关闭联动待办；巡检异常口径改为仅「发现故障」；导出附带快照字段。
- `src/views/warning/index.vue`：阈值配置面板（新建/编辑草稿、保存、发布）、版本与生效时间列、真实统计、发布/停用留档表。
- `src/views/waterlevel/index.vue`：预警级别/配置版本/判定时间列、真实统计、全量重判入口。
- `src/views/inspection/index.vue`：级别/版本/待办来源列、阈值待巡检统计。
- `src/data/seed.ts`：三个模块改为可跑通链路的数值样例（停用旧版+新版生效、已调整旧版+新版生效、草稿、归档留档、无配置站点），新增 `warningAudit` 留档。
- `scripts/verify-warning-chain.mjs`（新增）：六条链路场景验证。
